# 実装ロードマップ

## Phase 0: 調査と技術選定

アプリプロジェクトを作る前に、技術的な土台を決めます。

- 対応する最小 macOS バージョンを決める
- SwiftUI の表機能と AppKit `NSTableView` のどちらを中心にするか評価する
- MP3 / ID3v2 の読み書きライブラリを調査する
- 既存ネイティブライブラリをラップするか、ID3v2 処理を直接実装するか決める
- UI から使う共通メタデータモデルを定義する
- 手動検証用の小さな MP3 サンプルを用意する

MP3 / ID3v2 の読み書き技術調査は [タグ読み書き技術調査](tagging-research.md) にまとめています。MVP では `ID3TagEditor` を第一候補として採用し、将来 `TagLib` へ切り替えられる薄いタグ処理境界を置く方針です。

### 開発環境と最低対応 OS

初期実装では以下を基準にします。

- 最低対応 OS: macOS 14 Sonoma
- 開発環境: Xcode 26.3 以降
- Swift: Swift 6 language mode
- SDK: 開発時点の最新安定版 macOS SDK を使い、deployment target は macOS 14 に固定する

macOS 14 を最低対応にする理由は、SwiftUI の現代的な macOS アプリ構成を使いつつ、過度に新しい OS へ利用者を限定しないためです。Liner は開発初期から Mac 専用アプリとして作るため、古い OS 互換よりも、表編集、インスペクタ、シート、ドラッグ&ドロップ、Undo、ファイルアクセス権限まわりを素直に実装できる土台を優先します。

Xcode は Xcode 26.3 以降を基準にします。Xcode 26 系は Swift 6 language mode に対応しており、初期コードから Swift 6 前提の並行性・型安全性を意識して進めます。ただし、Xcode 26.4 以降のようにより新しい macOS を開発環境へ要求する版があるため、プロジェクト設定としては「Xcode 26.3 以降で開けること」を当面の下限にします。

### SwiftUI / AppKit 方針

Liner のアプリ構造は SwiftUI を中心にします。

- ウィンドウ、サイドバー、ツールバー、インスペクタ、シート、設定画面は SwiftUI で実装する
- アプリ状態、選択状態、変更追跡、保存前プレビューは SwiftUI から扱いやすいモデルとして設計する
- macOS 標準のメニュー、ショートカット、Undo 連携は必要に応じて AppKit と接続する

一方で、中央のスプレッドシート風編集テーブルは AppKit `NSTableView` を優先して検証します。Liner の中核体験は、多数行・多数列のセル直接編集、範囲選択、コピー&ペースト、キーボード移動、変更表示です。SwiftUI `Table` は一覧表示には向いていますが、Excel ライクな編集操作を細かく制御するには制約が出やすいため、初期実装では `NSViewRepresentable` で `NSTableView` を SwiftUI に組み込みます。

AppKit への依存は表編集、ファイルパネル、メニュー/Undo 連携など、macOS ネイティブ API が明確に有利な部分に限定します。アプリ全体を AppKit ベースにはせず、SwiftUI の画面構成の中に AppKit の強い部品を差し込む方針にします。

## Phase 1: macOSアプリ骨格作成

最初の macOS アプリ構造を作ります。

- Xcode プロジェクトまたは Swift Package 構成を作成する
- メインウィンドウを作成する
- サイドバー、ツールバー、中央の表、右側インスペクタの領域を作る
- Finder からファイルやフォルダを開けるようにする
- アプリウィンドウへのドラッグ&ドロップに対応する
- この段階では、完全なタグ編集ではなくアプリ構造に集中する

## Phase 2: MP3タグ読み込み

MP3 メタデータをアプリ内モデルへ読み込みます。

- 選択されたファイルやフォルダから MP3 ファイルを検出する
- 各ファイルから ID3v2 メタデータを読み込む
- テーブルの行として表示する
- 欠損フィールドや読み込みエラーを分かりやすく表示する
- 元ファイル URL、元メタデータ、編集中メタデータを分けて保持する

## Phase 3: Excelライクな表編集

表を主要な編集画面として実用化します。

- セルの直接編集に対応する
- 複数セルのコピー&ペーストに対応する
- 行選択と範囲選択に対応する
- 一般的なキーボード移動に対応する
- 元の値から変更されたフィールドを追跡する
- ファイルへ即時保存せず、編集中の値として分かりやすく表示する

## Phase 4: タグ書き込み

編集した MP3 メタデータをファイルに保存します。

- 変更された ID3v2 タグを MP3 ファイルへ書き込む
- 可能な限り、変更していないフィールドは保持する
- 文字エンコーディングを安全に扱う
- ファイルごとの書き込み成功・失敗を表示する
- 編集内容が意図せず保存されないよう、明確な保存境界を設ける

## Phase 5: 連番、貼り付け、一括編集

1ファイルずつ編集するタグエディタより速く作業できる機能を追加します。

- 1つの値を選択行へ下方向に貼り付ける
- トラック番号を連番生成する
- `01`, `02`, `03` のようなゼロ埋めに対応する
- 選択列に対する簡単な検索・置換に対応する
- 選択フィールドのクリアに対応する
- すべての一括操作を、変更追跡モデル上でプレビュー可能にする

## Phase 6: ファイル名テンプレートリネーム

メタデータをもとにファイル名を変更します。

- `{track} - {title}` のようなテンプレート構文を定義する
- `{artist}`, `{album}`, `{albumArtist}`, `{disc}`, `{track}`, `{title}` などを使えるようにする
- macOS で問題になる文字をファイル名から安全に除去・置換する
- 適用前に変更前後のファイル名をプレビューする
- ファイル名衝突を事前に検出する
- タグ書き込みとファイル名変更は内部的に別操作として扱う

## Phase 7: カバーアート設定

選択ファイルへのアートワーク編集を追加します。

- インスペクタまたはアートワーク領域への画像ドラッグ&ドロップに対応する
- 現在の選択に対するアートワークをプレビューする
- 1つの画像を複数選択中のトラックに適用する
- ID3v2 のカバーフレームへ画像を書き込む
- アートワーク書き込み失敗をファイルごとに表示する

## Phase 8: 差分プレビュー、Undo、安全性強化

対応形式を増やす前に、信頼して使える土台を強化します。

- 保留中のタグ変更とファイル名変更を確認するレビューシートを追加する
- 保存前のアプリ内編集に Undo を対応させる
- 初回書き込み前のバックアップ挙動を検討する
- 破壊的または曖昧な操作には明確な警告を表示する
- 部分的な保存失敗が起きた場合の復旧導線を用意する

## Phase 9: FLAC対応検討

MP3 ワークフローが固まった後に FLAC 対応を追加します。

- Vorbis Comment を読み込む
- FLAC picture block を読み込む
- FLAC フィールドを Liner 共通メタデータモデルへマッピングする
- 編集した FLAC タグを安全に書き込む
- MP3 と FLAC が混在するフォルダを同じ表で扱えるか検証する

## 初期受け入れ基準

最初の実用ビルドでは、ユーザーが MP3 のアルバムフォルダを読み込み、表でアルバム情報を編集し、トラック番号を生成し、カバーアートを設定し、変更をプレビューしてから ID3v2 タグを保存できる状態を目指します。
